# ТЗ — Менеджер паролей «Qwerty123»

**Название проекта:** «Qwerty123»
**Цель:** Создать десктопный менеджер паролей для локального хранения учетных данных пользователя. Учетные данные хранятся локально, а пароли — в зашифрованном виде.
**Пользователь:** Пользователи интернета, которые хотят безопасно хранить свои учетные данные и использовать сложные, уникальные пароли для разных сайтов.

## Функциональные требования
* **REQ-01.** Пользователь может добавлять, редактировать и удалять учетные данные (название сайта/URL, логин, пароль, категория). Поля «Название сервиса» и «Пароль» являются обязательными. Поле ввода «Логин» совмещено с Email (отдельного поля для ввода email нет).
* **REQ-02.** Пользователь может группировать и фильтровать сохраненные учетные записи по категориям (например, соцсети, банки, почта).
* **REQ-03.** Пользователь может в один клик скопировать логин или пароль в буфер обмена.
* **REQ-04.** Программа должна иметь встроенный генератор паролей с возможностью выбора трех уровней сложности:
  1. *Самый сложный:* 3 соединенных через дефис "-" строки длиной 6 символов (латиница в разном регистре и цифры). Пример: `aB3DX9-Km2zP1-7qRtWb`.
  2. *Полегче:* 2 соединенные через дефис "-" строки длиной 6 символов (только строчные латинские буквы и цифры). Пример: `x7m2a1-p9k4e0`.
  3. *Самый простой:* Сплошная строка длиной 6 или 8 символов, состоящая только из цифр (цифровой PIN-код) или только из строчных букв. Пример: `491037` или `qwerty`.
* **REQ-05.** Программа должна запрашивать мастер-пароль при старте. Из введенного мастер-пароля генерируется ключ шифрования (с помощью библиотеки cryptography). Программа использует этот ключ для проверки доступа к данным: если ключ верный — доступ открывается и данные успешно считываются, если неверный — перехватывается ошибка InvalidToken и выводится сообщение об ошибке.

## Данные
**Что храним:** Названия сайтов/сервисов (URL-адреса), логины (совмещенные с email), зашифрованные пароли пользователей, а также категории для сортировки.
**Где храним:** Локально на компьютере пользователя в базе данных SQLite. Структура состоит минимум из двух логически связанных таблиц:
1. Таблица учетных записей (`accounts`/`credentials`).
2. Таблица категорий (`categories`).
Сам мастер-пароль и ключ шифрования в открытом виде в системе не сохраняются.

## Ошибки и особые ситуации
* **ERR-01.** Если при входе введен неверный мастер-пароль, программа блокирует доступ к данным, перехватывает ошибку библиотеки шифрования и выдает предупреждение «Неверный пароль».
* **ERR-02.** Если база данных SQLite повреждена, отсутствует или заблокирована другим процессом, программа должна корректно обработать исключение (`sqlite3.Error`) и уведомить пользователя, избегая аварийного завершения (падения).
* **ERR-03.** Если пользователь пытается добавить аккаунт с пустыми обязательными полями (Название сервиса или Пароль), программа прерывает операцию и подсвечивает незаполненные поля.

## Критерий готовности
* В проекте используется несколько форм (окно авторизации/блокировки и главное окно приложения).
* Реализованы чтение, добавление, удаление и изменение данных в SQLite.
* Реализована фильтрация и группировка сохраненных учетных записей по категориям.
* Реализовано копирование логина или пароля в буфер обмена в один клик.
* В полной мере функционируют все 3 режима встроенного генератора паролей (в зависимости от выбранной сложности).
* Реализовано шифрование секретных значений (паролей) перед записью в SQLite и их расшифровка только после корректного ввода мастер-пароля (с использованием готовой библиотеки `cryptography`). При неверном вводе доступ к данным блокируется.
* Используется файл `requirements.txt` для внешних зависимостей.
* Итоговая версия приложения собирается в один `.exe` файл.
